# Campus Equipment Booking API

TypeScript/Hono backend for reserving shared equipment (cameras, projectors, meeting rooms) without overlapping bookings.

## 1. Assumptions

Recorded at the start of the test (minutes 0-10). These match `API_CONTRACT.md`.

- Times are ISO 8601 strings in UTC, e.g. `2026-10-20T09:00:00.000Z`.
- A booking that ends at 11:00 and another that starts at 11:00 for the same equipment is **not** a conflict (back-to-back is allowed).
- Two bookings for the same equipment conflict when `existing.startAt < new.endAt AND existing.endAt > new.startAt`.
- `PATCH` accepts partial fields. The combined result (stored values + changes) must still pass all validation, including the overlap check, which ignores the booking being edited.
- Booking `id` values are generated by the server.
- Equipment is seeded, not created through the API. The API only exposes `GET /equipment`.
- If `equipmentId` is missing or not a string, the API returns `400` (invalid data). If it is a valid string but no such equipment exists, the API returns `404` (the referenced resource was not found).
- `borrowerName` and `equipmentId` are required. `purpose` is optional on create.
- Malformed JSON bodies and unknown routes return JSON errors in the form `{ "error": "..." }`.

## 2. Tech Stack

- Language: TypeScript
- Framework: Hono
- Database: Cloudflare D1 (local, via `wrangler dev`), accessed with parameter binding only
- Testing: `curl`

## 3. How to Run

> Adjust script names to match the starter repo, and test from a clean clone before submitting.

```bash
# 1. Install dependencies
npm install

# 2. Create tables and seed equipment (local D1)
npx wrangler d1 execute DB --local --file=./schema.sql

# 3. Start the server
npx wrangler dev
```

The server listens on port: `8787`

## 4. Base API URL

Base URL used for testing: `http://localhost:8787/api`

## 5. Quick Example

```bash
# List equipment
curl -i http://localhost:8787/api/equipment

# Create a booking
curl -i -X POST http://localhost:8787/api/bookings \
  -H "Content-Type: application/json" \
  -d '{
    "equipmentId": "eq-1",
    "borrowerName": "Somchai Jaidee",
    "startAt": "2026-10-20T09:00:00.000Z",
    "endAt": "2026-10-20T11:00:00.000Z",
    "purpose": "Class presentation"
  }'
```

## 7. Schema / ERD

**equipment**

| Column | Type | Notes |
|---|---|---|
| id | TEXT | Primary key |
| name | TEXT | Required |
| location | TEXT | Required |

**bookings**

| Column | Type | Notes |
|---|---|---|
| id | TEXT | Primary key, generated by server |
| equipmentId | TEXT | Foreign key to `equipment.id` |
| borrowerName | TEXT | Required |
| startAt | TEXT | ISO 8601 UTC |
| endAt | TEXT | ISO 8601 UTC, must be after `startAt` |
| purpose | TEXT | Optional |

Relationship: one equipment has many bookings (`equipment 1 --- * bookings`).

Seeded equipment: `eq-1` Projector A (Building 1), `eq-2` Camera B (Building 2).
