# API Contract: Campus Equipment Booking API

## 1. Base URL

`http://localhost:8787/api`

All paths below are relative to this URL.

## 2. Conventions

- All requests and responses use JSON (`Content-Type: application/json`). `DELETE` success has no body.
- Times are ISO 8601 UTC strings, e.g. `2026-10-20T09:00:00.000Z`.
- Booking `id` values are generated by the server. Clients never send an `id`.
- Every error response uses this format:

```json
{ "error": "A message understandable to a user or developer" }
```

## 3. Endpoints Summary

| Method | Path | Success | Purpose |
|---|---|---:|---|
| GET | `/equipment` | 200 | List equipment |
| GET | `/bookings` | 200 | List bookings |
| GET | `/bookings/:id` | 200 | Get one booking |
| POST | `/bookings` | 201 | Create a booking |
| PATCH | `/bookings/:id` | 200 | Update a booking |
| DELETE | `/bookings/:id` | 204 | Delete a booking |

## 4. Endpoint Details

### 4.1 GET /equipment

Request body: none.

Success `200`:

```json
[
  { "id": "eq-1", "name": "Projector A", "location": "Building 1" },
  { "id": "eq-2", "name": "Camera B", "location": "Building 2" }
]
```

Errors: none expected.

### 4.2 GET /bookings

Request body: none.

Success `200`:

```json
[
  {
    "id": "bk-1",
    "equipmentId": "eq-1",
    "borrowerName": "Somchai Jaidee",
    "startAt": "2026-10-20T09:00:00.000Z",
    "endAt": "2026-10-20T11:00:00.000Z",
    "purpose": "Class presentation"
  }
]
```

An empty list returns `200` with `[]`.

Errors: none expected.

### 4.3 GET /bookings/:id

Request body: none.

Success `200`: a single booking object (same shape as above).

Errors:

| Code | When |
|---|---|
| 404 | No booking with this `id` |

### 4.4 POST /bookings

Request body:

```json
{
  "equipmentId": "eq-1",
  "borrowerName": "Somchai Jaidee",
  "startAt": "2026-10-20T09:00:00.000Z",
  "endAt": "2026-10-20T11:00:00.000Z",
  "purpose": "Class presentation"
}
```

Success `201`: the created booking, including the server-generated `id`.

```json
{
  "id": "bk-1",
  "equipmentId": "eq-1",
  "borrowerName": "Somchai Jaidee",
  "startAt": "2026-10-20T09:00:00.000Z",
  "endAt": "2026-10-20T11:00:00.000Z",
  "purpose": "Class presentation"
}
```

Errors:

| Code | When | Example message |
|---|---|---|
| 400 | Malformed JSON, missing or wrongly typed field, invalid date, or `startAt` not before `endAt` | `"startAt must be before endAt"` |
| 404 | `equipmentId` is a valid string but no such equipment exists | `"Equipment not found"` |
| 409 | Time overlaps an existing booking for the same equipment | `"Equipment is already booked for this time"` |

### 4.5 PATCH /bookings/:id

Request body: any subset of `equipmentId`, `borrowerName`, `startAt`, `endAt`, `purpose`. Example:

```json
{ "endAt": "2026-10-20T12:00:00.000Z" }
```

The stored booking is merged with the supplied fields, and the merged result must pass every rule in section 5, including the overlap check (which ignores the booking being updated).

Success `200`: the full updated booking.

Errors:

| Code | When | Example message |
|---|---|---|
| 400 | Malformed JSON, empty body, wrongly typed field, invalid date, or merged `startAt` not before merged `endAt` | `"startAt must be before endAt"` |
| 404 | No booking with this `id`, or new `equipmentId` does not exist | `"Booking not found"` |
| 409 | Merged time overlaps another booking for the same equipment | `"Equipment is already booked for this time"` |

### 4.6 DELETE /bookings/:id

Request body: none.

Success `204`: no body.

Errors:

| Code | When |
|---|---|
| 404 | No booking with this `id` |

## 5. Field Rules (Validation)

| Field | Type | Create | Update | Rules |
|---|---|---|---|---|
| `id` | string | server-generated | not allowed | Never accepted from the client |
| `equipmentId` | string | required | optional | Non-empty string. Must exist in `equipment` |
| `borrowerName` | string | required | optional | Non-empty after trimming |
| `startAt` | string | required | optional | Valid ISO 8601 date-time. Must be before `endAt` |
| `endAt` | string | required | optional | Valid ISO 8601 date-time. Must be after `startAt` |
| `purpose` | string | optional | optional | String if provided |

## 6. Error Codes and Why

| Code | Used when | Reason |
|---|---|---|
| 400 Bad Request | The request itself is malformed or invalid: bad JSON, missing or wrongly typed fields, unparseable dates, `startAt` not before `endAt` | The client can fix it by changing the request data |
| 404 Not Found | The booking `:id` does not exist, or the referenced `equipmentId` does not exist | The resource named in the URL or body cannot be found |
| 409 Conflict | The request is valid, but the time overlaps an existing booking for the same equipment | The data is well formed but clashes with the current state of the server |

Unknown routes also return a JSON error (`404`, `{ "error": "Route not found" }`).

## 7. Business Rules

- **Overlap rule:** two bookings for the same equipment conflict when `existing.startAt < new.endAt AND existing.endAt > new.startAt`.
- **Back-to-back allowed:** a booking ending at 11:00 and another starting at 11:00 do not conflict.
- **Different equipment:** bookings for different equipment never conflict.
- **Create and update:** the overlap check runs on `POST` and `PATCH`. On `PATCH`, the booking being edited is excluded from the check.
- **Security:** all database queries use parameter binding. Request data is never concatenated into SQL.

## 8. Assumptions

These match the Assumptions section in `README.md`.

- Times are ISO 8601 UTC strings.
- Back-to-back bookings are not conflicts.
- `PATCH` accepts partial fields, and the merged result must still be valid.
- Booking ids are generated by the server.
- Equipment is seeded, not created through the API.
- Missing or non-string `equipmentId` returns `400`. A valid but non-existent `equipmentId` returns `404`.
- `purpose` is optional on create.
